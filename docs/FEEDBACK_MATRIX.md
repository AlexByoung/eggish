# 遊戲音樂與音效設計規劃：蛋仔快跑

本文件定義《蛋仔快跑》的音樂、音效與聲音回饋方向。內容屬於設計規劃，不代表已批准安裝第三方依賴、加入外部音檔或修改遊戲核心邏輯。

## 設計總原則

整體聲音調性延續蛋仔的個性：**軟綿綿、慢半拍、不緊繃**。

即使是死亡音效，也不使用尖銳警報聲，而是帶點幽默、洩氣感的「哦……又來了」語氣。

### 音色偏好

- 木琴
- 馬林巴
- 鈴鐺
- 氣泡音
- 圓潤的正弦波
- 柔和的三角波

### 避免使用

- 尖銳鋸齒波
- 生硬金屬敲擊
- 高壓迫感警報聲
- 過度響亮或搶過背景音樂的持續音
- 帶有懲罰感的死亡提示

## 一、音樂（BGM）

### 1. 主選單音樂

| 欄位 | 規格 |
|---|---|
| 情境 | 玩家打開遊戲第一個聽到的聲音，目標是先讓人放鬆下來 |
| 風格 | 慵懶午後感，像打盹前隨口哼的小曲，帶慢速搖擺 |
| 樂器 | 木琴／馬林巴主旋律、烏克麗麗撥弦、輕巧木魚或鈴鼓節奏 |
| 速度與調性 | 約 90–100 BPM、大調 |
| 播放要求 | 可無縫循環；進入遊戲時柔和淡出 |

#### AI 音樂生成 Prompt

```text
Cozy lo-fi marimba and ukulele lullaby, playful but relaxed,
major key, soft bells, gentle swing rhythm, candy-colored
dreamy mood, seamless loop, no vocals, 90 BPM
```

### 2. 關卡循環音樂

| 欄位 | 規格 |
|---|---|
| 情境 | 遊玩中的背景音樂，比主選單更有跳躍律動感，但不能搶戲 |
| 風格 | 俏皮輕快，貼合平台跳躍節奏 |
| 樂器 | 馬林巴主旋律、清脆輕巧的打點節奏、少量口哨或哼唱式音色 |
| 速度 | 約 110–120 BPM，基準建議 115 BPM |
| 結構 | 建議分成底層 Loop 與可疊加緊張層 |
| 播放要求 | 可無縫循環；選單／關卡切換時淡入淡出 |

分層製作可让未來的危險段落疊加聲音層次，不必整首切換。

#### AI 音樂生成 Prompt

```text
Upbeat playful marimba platformer loop, bouncy percussion,
whimsical whistle accents, candy pastel mood, energetic but
cute, seamless 8-bar loop, no vocals, 115 BPM
```

### 3. 過關短音（Jingle）

| 欄位 | 規格 |
|---|---|
| 情境 | 玩家抵達終點、完成關卡的瞬間 |
| 風格 | 小小的報喜感；讓人會心一笑，但不誇張慶祝 |
| 樂器 | 鈴鐺與木琴滑音 |
| 音型 | 從低到高快速上揚並收尾 |
| 長度 | 約 2–3 秒 |

#### AI 音樂生成 Prompt

```text
Short 2-second victory jingle, bright bells and xylophone
glissando rising up, cheerful but understated, candy game
level-clear chime
```

## 二、音效（SFX）回饋矩陣

音效優先考慮使用程序參數合成，以維持一致音色並縮小檔案體積。候選方式包括 jsfxr、ZzFX 或專案內自有的等效輕量合成器。

> 導入 ZzFX 或任何第三方程式庫前，仍需取得明確批准。若未批准新增依賴，應以專案內原生 Web Audio 程式碼實作等效功能。

| 回饋事件 | 觸發時機 | 音色與音型 | 長度／循環 | 優先級 | 播放與防重複要求 |
|---|---|---|---|---|---|
| **跳躍** | 起跳實際成立的瞬間 | 正弦波由低快速掃到高，像 QQ 糖彈起的短促「咻」聲 | 0.1–0.15 秒 | P1 | 只在跳躍成功時播放；緩衝輸入不可重複觸發 |
| **落地** | 從空中轉為穩定著地 | 低頻短促「啵」聲，柔軟衰減，沒有金屬感 | 0.1 秒內 | P1 | 需設最短間隔，避免站在移動平台或箱子上每幀播放 |
| **死亡** | 尖刺或掉出世界造成一次有效死亡 | 滑音下降並帶洩氣感，像無奈的「哦……」 | 0.3–0.5 秒 | P1 | 與一次死亡計數一一對應；重複 overlap 不可疊音 |
| **推箱子** | 玩家確實推动箱子時 | 短促重複摩擦噪音，帶 QQ 彈性，近似咬軟糖的「嘎吱」 | 隨推動循環 | P2 | 只有箱子實際位移時播放；停止推动后快速淡出 |
| **機關按鈕** | 壓力板由未按下切換為按下 | 清脆短促的「啵」聲，像戳軟糖表面 | 0.1 秒內 | P1 | 只在狀態邊沿播放；持續壓住時不重複 |
| **門** | 機關門開始開啟 | 木質／糖果罐蓋聯想的「叩～嗤」聲 | 約 0.3 秒 | P1 | 不使用金屬滑軌聲；重新開門可播放，安全等待關門時不亂觸發 |
| **移動平台** | 平台正在移動 | 柔和、低音量的「咻咻」摩擦聲 | 無縫循環 | P2 | 低於 BGM；暫停、清理或關卡切換時必須停止 |
| **小彈簧** | 壓縮結束、玩家實際取得向上速度的同一幀 | 兩段圓潤快速上揚音，像小顆 QQ 糖回彈 | 約 0.15 秒 | P1 | 只在有效上方接觸後播放；與短冷卻及 pending 狀態共用防重複 |
| **UI 選擇（Hover）** | 游標或鍵盤焦點進入新選項 | 極短高頻單音「叮」 | 約 0.05 秒 | P2 | 同一元素持續 hover 不重播；停用按鈕不播放 |
| **UI 確認（Select）** | 確認按鈕、進入選項 | 雙音階上揚「叮鐺」，比 Hover 更完整 | 約 0.15 秒 | P1 | 在有效操作成立後播放；轉場鎖定期間不重複 |
| **過關短音** | 關卡首次進入完成狀態 | 鈴鐺＋木琴快速上揚 | 2–3 秒 | P1 | 每次有效過關只播放一次；重玩後可再次觸發 |
| **火炮預警** | 可讀範圍內的炮台進入發射前警告 | 兩段柔和上揚提示，不使用尖銳警報 | 約 0.2 秒 | P1 | 每個發射週期只觸發一次；離開鏡頭後不播放 |
| **火球發射** | 火球實際從物件池啟用 | 圓潤、短促的下降氣泡音 | 約 0.2 秒 | P1 | 設冷卻與最大重疊；物件池耗盡時不播放空發射音 |
| **交替尖刺預警** | 鏡頭附近的 A/B 組進入下一次伸出前的 warning 狀態 | 極低音量的柔和雙音提示，不使用方波或尖銳警報 | 約 0.16 秒 | P1 | 由共享控制器在狀態邊沿播放；鏡頭外、重置時不播放，且限制重疊 |

## 三、音量與混音原則

| 類別 | 相對音量方向 | 備註 |
|---|---|---|
| 主選單 BGM | 中低 | 放鬆、不能壓過 UI 音效 |
| 關卡 BGM | 中低 | 保持存在感，但不干擾機關判讀 |
| 過關短音 | 中 | 可短暫突出，不需非常響亮 |
| 玩家動作 SFX | 中低 | 跳躍和落地要清楚但不疲勞 |
| 機關 SFX | 中 | 需協助玩家理解按鈕、門和平台關係 |
| 持續循環 SFX | 低 | 推箱子與移動平台必須低於旋律層 |
| UI SFX | 低至中低 | 頻繁操作時不可刺耳 |

### 全域控制要求

- 提供 Master、Music、SFX 三組獨立音量。
- 提供靜音切換。
- 設定需持久化，但不可影響關卡進度資料的有效性。
- 暫停時應暫停或柔和淡出 BGM 與持續循環 SFX。
- 恢復時不得同時啟動重複 Loop。
- 瀏覽器尚未取得使用者互動授權前，不強制播放音訊。

## 四、實作架構要求

### SFX 模組

未來實作時，將程序化音效集中到獨立的 `js/sfx.js`：

- 每個音效有清楚命名的參數設定。
- 音量、靜音、播放、循環、停止與防重複邏輯統一管理。
- 遊戲邏輯只呼叫語意化事件，例如 `playJump()`、`startBoxPush()`、`stopBoxPush()`。
- 合成參數不得散落在 `game.js`、`levels.js` 或 `mechanisms.js`。
- 不得為播放音效修改玩家速度、碰撞、死亡計數或機關狀態。

### 音樂框架

音樂音檔將另行提供。在音檔確定前，框架需預留：

- 主選單音樂載入與循環。
- 關卡音樂載入與循環。
- World 2 音樂使用獨立的 `world2Music` 事件；第 8 關進入時從 World 1 關卡音樂淡出並淡入新曲。
- 過關短音播放。
- 主選單与關卡之間的淡入淡出切換。
- 暫停、恢復、靜音與音量控制。
- 音檔缺失時安全跳過，不阻止遊戲啟動。
- 直接 `file://` 啟動的相容性評估。

建議未來音檔目錄：

```text
assets/
  audio/
    music/
    jingles/
```

## 五、程序化音效整合 Prompt

以下 Prompt 可供未來程式實作使用。它是需求摘要，不代表已批准使用指定第三方套件。

```text
請幫我在目前的 Phaser.js 專案裡，用 ZzFX（或等效的輕量程序化音效合成方式）
實作以下音效，全部用程式參數合成，不需要外部音檔：

1. 跳躍音效：正弦波，音高從低快速掃到高，時長約0.1-0.15秒，輕快活潑
2. 落地音效：低頻短促衰減音，時長0.1秒內，軟綿綿的觸感，不要清脆金屬聲
3. 死亡音效：滑音下降，帶點幽默洩氣感（像「哦…」的語氣），時長0.3-0.5秒，
   避免尖銳警報式音效
4. 推箱子音效：短促重複的摩擦噪音，帶Q彈感，可循環播放
5. 按鈕音效：清脆短促的「啵」聲，時長0.1秒內
6. 門音效：略帶木質/罐蓋開啟聯想的短音，時長約0.3秒，不要金屬滑軌聲
7. 移動平台音效：柔和的摩擦循環音，音量低，可無縫循環
8. UI選擇（hover）音效：極短高頻單音，時長0.05秒
9. UI確認（select）音效：雙音階上揚，時長0.15秒，比選擇音豐富

請把這些音效整理成一個獨立的 sfx.js 模組，統一管理音量與播放邏輯，
方便之後我要微調音色參數時能快速找到對應設定。

音樂部分（主選單音樂、關卡循環音樂、過關短音）我會另外提供音檔，
請先幫我寫好音樂載入與播放/循環切換的框架邏輯（例如切換場景時淡入淡出音樂），
之後我把檔案放進指定資料夾就能直接接上。
```

## 六、現成免費素材候選

若音樂不使用 AI 生成，可在 OpenGameArt.org 或 itch.io 免費音效／音樂包中搜尋：

- `cozy marimba loop`
- `cute platformer bgm`
- `candy game jingle`
- `soft ukulele lo-fi loop`

音效可在 freesound.org 搜尋並篩選 CC0 授權：

- `soft pop bubble`：按鈕／落地類
- `cute jump boing`
- `wooden door open soft`
- `squeaky friction loop`：推箱子／移動平台

### 外部素材要求

- 每個候選素材必須保存來源 URL、作者、授權類型與下載日期。
- 優先使用 CC0；其他授權需在採用前確認署名與再散布要求。
- 不可只根據搜尋關鍵字就視為可商用。
- 不可提交來源或授權不明的音檔。
- AI 生成音樂也需記錄工具、生成日期、Prompt 與當時適用條款。

## 七、未來關卡主題調音

第一個正式情緒關卡主題確定後，可在不改變整體聲音語彙的前提下微調機關音色。

例如「太妃糖林」的尖刺或機關音效，可以增加略微黏膩、拉扯的質感，呼應焦慮情緒的黏著感；但仍需避免尖銳、刺耳或帶懲罰感的聲音。

## 八、驗收原則

- 音訊關閉或載入失敗時，四關仍可正常完成。
- 每個一次性事件只觸發一次對應音效。
- 暫停、死亡、重置、重玩和關卡切換不留下重複 Loop。
- 聲音不得掩蓋重要視覺與機關回饋。
- 死亡聲音保持幽默、柔和，不製造壓迫感。
- 所有第三方音檔都有可追溯授權記錄。
- 程序化音效參數集中管理，沒有散落魔法數字。
- 完整／減少動效設定不應改變遊戲音效觸發邏輯。

## 九、階段六A實施狀態

- 已建立 `js/audio-config.js`，集中管理語義事件、分類音量、冷卻、最大實例數、循環與音樂淡入淡出參數。
- 已建立 `js/audio-manager.js`，負責程序化 SFX、音樂預載與切換、瀏覽器首次互動解鎖、Master／Music／SFX 音量、靜音、暫停恢復和清理。
- 已接入跳躍、落地、死亡、壓力板、門開啟、UI hover/select 與過關事件。
- 已接入小彈簧回彈事件；音效与玩家取得彈射速度同步，壓縮等待和冷卻期間不重播。
- 推箱子與移動平台循環已具備配置和 `startLoop()`／`stopLoop()` 生命週期介面，但尚未接入持續觸發判斷，留待後續機關回饋階段驗證後啟用。
- 正式主選單與關卡音樂檔尚未提供；配置路徑保持 `null`，缺失時靜默運行。後續只需將檔案放入 `assets/audio/` 並修改 `js/audio-config.js`。
- 第四關踏上首塊平台後自動開始倒數，只沿用既有 `door` 語義事件，不播放按鈕音，也不新增第二套音效或散落的合成參數；倒數警告目前只使用視覺色塊。
